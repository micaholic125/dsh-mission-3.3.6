# 05 · 安全规范

## 一、安全底线

1. **动游戏文件前必须备份**，可还原才算完成。
2. **游戏运行中禁止离线写入**：检测到 `gamemd.exe` / `MentalOmegaClient.exe` 在跑，就停下。
3. 所有写操作：先写 `.tmp` → 校验 → 替换，**不直接覆盖**。
4. 关键操作留痕：改了什么、何时、改前 sha1。
5. **只改值，不改结构**；只改点名的单位，不扩大范围。

## 二、备份策略

```
backup/20261111_153012/
  rulesmo.ini            # 部署前的旧文件（如不存在则写 NO_EXISTING_FILE.txt）
  sha1_manifest.txt      # 文件名 + sha1
```

- 部署前必做；目录名用 `YYYYMMDD_HHMMSS`。
- 不删除 `backup/` 下任何历史快照——它们是部署/回滚的还原依据。

## 三、回滚

| 场景 | 做法 |
|---|---|
| 撤销本次平衡改动 | 删除 `<游戏安装目录>\rulesmo.ini` |
| 恢复到某一批之前 | 从 `backup/<时间戳>/rulesmo.ini` 复制回去 |
| 完全恢复原版 | 同上，或直接删覆盖文件（MIX 从未被改动） |

> 覆盖文件是"增量文件"，MIX 内原件完整无损，因此**回滚永远是安全的**。

## 四、禁止事项

- ❌ 修改/删除 `<游戏安装目录>` 下任何 `.mix`、`.exe`、`.dll`
- ❌ 在未备份的情况下覆盖已有 `rulesmo.ini`
- ❌ 游戏运行时写文件
- ❌ 为绕过权限限制而切换 shell / 提升权限 / 改 ACL
- ❌ 改动未经用户点名的单位
- ❌ 提交游戏本体与大二进制文件进版本库

## 五、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| MO 客户端自动更新覆盖/忽略外置 ini | 改动失效 | 检查 `RA2MO.ini` 的 `CheckforUpdates`；失效时改用其它注入方式前先问用户 |
| 中文名对应多个 ID（玩家版/AI 版） | 改错对象，游戏里没变化 | 查 `单位名录_自检报告.md`，必要时要求用户在需求里写 ID |
| 数值越界导致崩溃或负值 | 游戏异常 | `docs/03-设计规范.md` 的上下限校验 |
| 武器射速改在单位节而非武器节 | 无效 | 单位的 `ROF` 在武器节，改前确认 |
| 覆盖文件后游戏读档异常 | 存档与规则不匹配 | 保留回滚路径；大改前先在**新存档**测试 |
| 同时装多个 MOD 工具（如内存修改器） | 冲突难定位 | 本脚本只做文件覆盖，测试时关掉其它修改器 |

## 六、日志要求

- 每天一篇 `devlog/YYYY-MM-DD.md`，四段必填。
- 部署、覆盖、删除等动作必须记录：**sha1 + 时间 + 条数**。
- 回滚也必须记一条。
