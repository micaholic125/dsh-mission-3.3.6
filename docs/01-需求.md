# 01 · 需求与范围

## 目标

为《心灵终结》（Mental Omega）3.3.6 制作一份**数值平衡性脚本**：通过外置同名 `rulesmo.ini` 覆盖，调整指定单位的造价、血量、装甲、速度、视野、武器伤害/射程/射速等数值型参数。

## 范围

**做：**
- 只改 `rulesmo.ini` 中**已存在**的键的值。
- 一次部署只处理用户明确点名的一批单位。
- 部署前备份、部署后复核、可一键回滚。

**不做：**
- 不新增/删除单位、武器、节。
- 不改美术、音效、地图、AI 脚本。
- 不修改 `D:\Mental Omega` 下的任何 `.mix` / `.exe`。
- 不做内存修改（实时作弊式改值），只做离线文件覆盖。

## 名词约定

| 名词 | 含义 |
|---|---|
| 基准文件 | `rulesmo_original.ini`，从 `expandmo99.mix` 抽出的原版，**只读** |
| 覆盖文件 | `D:\Mental Omega\rulesmo.ini`，我们生成并部署的文件 |
| 名录 | `单位名录.csv`，中文名 ↔ 节点 ID ↔ 数值 |
| 玩家版 / AI 版 | 同一单位在规则里可能有两个 ID（如 `STARDUSTB` 玩家可造、`STARDUST` 仅 AI），二者参数可不同 |
| 差异条数 | `ini_compare.py` 报告的"节+键"级改动数量 |

## 单位标识的两套名字

- **节点 ID**：`[APOC]` 这种，改数值只认它。
- **中文名**：`天启坦克` 这种，用户报需求用。由 `unit_names_cn_merged.json` 映射到 ID。

> ⚠️ 中文名**不唯一**。`悖论引擎` 同时映射 `STARDUSTB` 与 `STARDUST`。
> 用户报中文名时，先查 `单位名录_自检报告.md` 的"同中文名分组"，**必须确认要改哪个 ID**，禁止猜测。

## 验收标准

1. 差异条数 == 用户名单条数（`ini_compare.py` 复核）。
2. 覆盖文件能正常加载，游戏可进入遭遇战。
3. 目标数值在游戏内可见地变化。
4. 删除覆盖文件后，数值恢复原版。
5. 每步在 `devlog/` 留痕，危险操作留 sha1 与时间。
