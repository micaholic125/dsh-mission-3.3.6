# 02 · 技术方案

## 一、数据从哪来

`<游戏安装目录>\expandmo99.mix`（11,004,015 字节）内含全部规则文件，`rulesmo.ini` 就在其中。
玩家用自己的游戏目录即可复现，直接跑 `python tools/extract_rules.py --game-dir "<游戏安装目录>"`。

### 关键结论：这个 MIX **没有加密**

最初按标准 Westwood/RA2 格式解析失败（索引表像乱码），实测推翻"需要 Blowfish 解密"的判断：

- 全文 **90.85% 是可打印 ASCII**，熵 5.755 → 明文特征；
- 头部约 370 字节是被混淆的索引表，**但完全不必读它**；
- 每个 INI 都带团队注释横幅（`;;;;Mental Omega 3.3.6 XXX FILE;;;;` … `END OF XXX FILE`），可据此**直接切割**。

### 提取方法（已实现并验证）

```
规则文件起点：`;;;;Mental Omega 3.3.6 RULES CONTROL FILE;;;;` 行首  → 偏移 2,436,130
规则文件终点：`END OF RULES FILE` 行末（含换行）                     → 偏移 4,726,451
               紧随其后的 `;;;` 收尾行只作结束哨兵，不计入正文
结果：2,290,321 字节 / 4,725 节 / 108,275 键
```

交叉验证：作者在本项目之前维护的另一份规则改动副本（不入库）同样是 **4,725 节**，与抽取值完全一致。

包尾部还有一张文件名数据库（`local mix database.dat`，格式为"长度字节 + 文件名"），30 个文件全名可见：
`rulesmo.ini / artmo.ini / aimo.ini / soundmo.ini / evamo.ini / thememo.ini / lunarmo.ini /
urbannmo.ini / urbanmo.ini / desertmo.ini / temperatmo.ini / snowmo.ini / missionmo.ini /
mapselmo.ini / mpmodesmd.ini / mpunholymd.ini / battlemo.ini / uimd.ini / …`

## 二、怎么生效

**外置同名覆盖**：把 `rulesmo.ini` 放进 `<游戏安装目录>`，引擎优先读目录下的同名文件，MIX 内的原件不动。

- 依据：外置同名文件的优先级高于 MIX 内文件；该路线已在本项目完成实机部署与回滚演练
  （见 `docs/04-执行步骤.md` 的 Phase 3 / Phase 4）。
- 回滚：删掉 `<游戏安装目录>\rulesmo.ini` 即恢复原版。
- 风险：MO 客户端 `RA2MO.ini` 中 `CheckforUpdates=True`，理论上可能重新拉取补丁；若发现覆盖失效，先查此项。

## 三、工具链

| 脚本 | 职责 | 关键保证 |
|---|---|---|
| `tools/extract_rules.py` | 抽原版基准 | 按团队注释横幅定位 `rulesmo.ini` 起止，逐字节复现 2,290,321 字节；输出前校验，不覆盖已有基准（除非 `--force`） |
| `tools/ini_edit.py` | 行级改值 | 改前校验节与键存在；保留注释/CRLF/编码（不凭空加 BOM）；`.tmp` → 校验 → 原子替换；sha1 变了才算成功 |
| `tools/ini_compare.py` | 语义比对 | 按 `[节]+键` 比，忽略注释与空白差异，输出 CHANGED/KEY_ADDED/… 分类计数 |
| `tools/build_override.py` | 基准 + 批次清单 → 覆盖文件 | 前置校验 + 独立复核 + 反向检查有无清单外改动 |
| `tools/deploy.py` | `check` / `deploy` / `rollback` | 进程检查、强制备份（含 sha1）、部署后校验 |
| `tools/make_release.py` | 打包可交付 zip | 双击安装/还原、使用说明、改动清单、SHA256SUMS |
| `tools/merge_names.py` | 合并中文名表（**一次性内部工具**） | 6 份社区汉化 `unit_names_cn*.json` → 1 份总表；源数据不随仓库分发 |
| `tools/make_unit_catalog.py` | 生成名录 | `单位名录.csv`，1,722 条 |
| `tools/check_catalog.py` | 名录自检 | 检出"同名不同 ID""玩家版/AI 版"等歧义，输出 `单位名录_自检报告.md` |
| `tools/devlog.py` | 开发日志 | 创建/追加当日日志 |

## 四、字段含义（改值前必须确认）

| 字段 | 所在 | 含义 |
|---|---|---|
| `Cost` | 单位节 | 造价（信用点） |
| `Strength` | 单位节 | 血量 |
| `Armor` | 单位节 | 装甲类型，取值是 `[ArmorTypes]` 的键名 |
| `Speed` | 单位节 | 移动速度（步兵约 4-8，载具 4-10，飞行器 20-40） |
| `Sight` | 单位节 | 视野 |
| `TechLevel` | 单位节 | 科技等级，`-1` 通常表示不可建造 |
| `Prerequisite` | 单位节 | 前置建筑，逗号分隔 |
| `Owner` | 单位节 | 可建造阵营，**为空表示谁都造不了（多为 AI 专用）** |
| `Damage` / `ROF` / `Range` / `Burst` | 武器节 | 伤害 / 射速(帧) / 射程 / 连发数 |

> 单位的 `ROF` 通常在**武器**节而不是单位节；改射速要去 `[WeaponTypes]` 指向的那一节。

## 五、验证手段

1. `ini_compare.py`：改动条数必须与名单一致。
2. 人工抽查：`ini_edit.py get <节> <键>` 读回确认。
3. 游戏内：进遭遇战看数值/手感。
4. 回滚：删覆盖文件后重新对比基准。
