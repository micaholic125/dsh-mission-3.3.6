# 2026-11-11 开发日志

## 完成

### 1. 环境修复：Bash 恢复可用
- 现象：`ops_bash` 持续报 `EXECUTOR_UNAVAILABLE ... link 'winuxcmd.exe' -> 'od.exe'`。
- 根因：`winuxcmd.exe` 同一 inode 的 **NTFS 硬链接数达 940**（上限 1024），每次建执行树还要 +154，历史残留执行树占满了配额。dsh-ops 只在"跨盘"时降级为复制，硬链接超限报 `UNKNOWN` 不认，直接抛错。
- 修复：把 payload 用**同字节副本原地替换**，使 inode 归零重来。
  - `nlink 940 → 1`，inode `562949953885085 → 1125899907463374`，**sha256 前后一致 `c588a847bb94b06f…`**。
  - 结果：`BASH_OK` / `MSYS_NT-10.0-26200` / `Python 3.14.7` / `Node v26.8.1`。
- 遗留：`D:\dsh-ops-exec\` 下 6 个历史执行树被拒绝删除（EPERM），**不影响功能，不再处理权限**。

### 2. 关键突破：`expandmo99.mix` 未加密
- 推翻前置假设"需要 MO 定制 Blowfish 解密"。
- 证据：全文 **90.85% 可打印 ASCII**、熵 5.755；头部约 370 字节是混淆索引表，**无需解析**。
- 方法：按团队注释横幅切割 —— 起点 `;;;;Mental Omega 3.3.6 RULES CONTROL FILE;;;;` @偏移 **2,436,130**，终点 `END OF RULES FILE` @ **4,726,451**。
- 产出 `rulesmo_original.ini`：**2,290,321 字节 / 4,725 节 / 108,275 键 / CRLF 118,761**。
- 交叉验证：用户既有工程 `D:\Default Project\scripts\rulesmo.mod.ini` 同为 **4,725 节**，完全吻合。
