# 开发日志机制

## 目录约定

```
devlog/
  README.md              # 本文件
  YYYY-MM-DD.md          # 每天一篇，文件名即日期
```

## 每篇必含四段（缺一段即视为未完成）

1. **完成**：今天实际做完的事，附证据（文件路径/命令结果/差异条数）
2. **代办**：明天或下一步要做的事，按优先级排
3. **风险**：已知隐患、未验证的假设、可能回滚的点
4. **下一步**：一句话说明下次开工从哪开始

## 生成方式

- **手动**：`python tools/devlog.py`（自动创建今天这篇并套模板；已存在则不覆盖）
- **自动（作者环境）**：作者曾用定时任务在固定时刻触发日志整理；投递时刻取决于会话是否活跃，
  可能延迟数小时，因此只作辅助手段，**日志内容以实际工作为准**。

## 内容要求

- 中文短句，结论先行。
- 危险操作（写游戏目录、覆盖文件）必须留 **sha1 + 时间**。
- 引用文件一律带路径，必要时带行号，如 `docs/03-设计规范.md:12`。
- 不写"待定""再看看"这类空话；要么写清楚，要么写进"风险评估"。

## 关于日志里的路径

日志中出现的游戏安装目录、工具与运行时位置等，都是**作者写作当时的本机环境**，
既不是本项目的规定，也不适用于其他人的机器。对外表述与可复现命令统一以
[`README.md`](../README.md)、[`CONTRIBUTING.md`](../CONTRIBUTING.md) 为准，
游戏目录一律写作 `<游戏安装目录>`。

## 关于日志里引用的提交哈希

2026-11-17 开源发布前重写过一次版本历史（把游戏数据文件从全部历史中移除），
因此早期日志里引用的旧提交短哈希（如 `b895eea`）已无法解析，属正常现象；
日志正文按当时原文保留，不做事后修改。
